**Authority:** Stormglass Master WDC (AI Start Here / Economy & Balance), Player Vision & Decisions, and the October 9 evidence-based *We Are Warriors* metadata comparison. ## Status terminology
- **SOURCE FIXED:** committed code changed; not automatically a device or balance pass.
- **AUTOMATED BUILD:** Vercel confirms the build passed. Build invokes `tsx --test tests/*.test.ts`, `tsc --noEmit`, then `vite build`.
- **DEVICE QA OPEN:** no recorded physical phone touch/animation/60-second battle run from this audit.
- **BALANCE OPEN:** no validated simulation of first hour, skill combinations, payout curves or 20-run real-player cohort.
- **RELEASED:** not claimed.

## Automated regression cases
- `tests/rules.test.ts`: Dungeon entry and free-continuation Keys, campaign Gold multiplier, Legends first-clear ownership (**9 test cases**).
- `tests/battleSim.test.ts`: determinism, one swing per attack cycle, spawn timing, Food spend, skill cooldown lock, dungeon kills without Gold, boss gate, Rush timer, defeat freeze, dead-target projectiles, interpolation (**32 test cases**, incl. frame-rate invariance at 5/30/60/120 FPS).
- `tests/storage.test.ts`: round-trip permanent save, legacy Legends migration, negative/nonfinite currency, damaged-save recovery (**4 test cases**).
- Vercel build now executes tests and TypeScript validation before compiling the site.
- A green deployment does **not** prove that the player can complete a battle or that UI is correct on an iPhone.

## Known unfinished or insufficiently verified systems
**Do not report these as working features merely because components exist:**
1. **P0 Combat architecture — SOURCE FIXED (2026-10-12):** Combat now runs in `src/logic/battleSim.ts`, a pure fixed-timestep (100ms) simulation with injected randomness, step-locked enemy spawns (pause-safe) and render interpolation; `App.tsx` holds one simulation ref and publishes a render copy per frame. Covered by `tests/battleSim.test.ts` (32 cases). Living non-boss enemies are held at `MAX_ALIVE_ENEMIES` = 6 (engineering limit pending owner approval); transient effects capped at 16. Still open: data-driven enemy wave tables, projectile retargeting, and recording player commands (only the seed is stored, so there is no portable action trace yet).
2. **P0 Playability:** Record device QA at 320×568 and 393×852, mouse/touch hitboxes, pause/resume, siege/boss completion, save/reload, short and long sessions, and background transitions.
3. **P0 Economy balance:** First Prestige ~1 hour and ~60s encounters are targets, not empirically validated. Require simulated cohorts, no-ad failure recovery and recorded playtest logs before tuning.
4. **P1 Unit choice:** Current/previous Age eligible roster appears, but the owner-approved three selectable logical troop slots and pre-battle loadout editor remain incomplete.
5. **P1 Dungeons:** Survival run protection for secured milestones, all difficulty curves, story scenes, and boss scaling remain in progress; four-mode interface is not proof of polished mechanics.
6. **P1 Events:** No isolated 72-hour Event economy/roster/currency/inventory/progress loop matching WDC has been verified in GitHub. A seasonal milestone screen is not that system.
7. **P1 Art:** Approved original pixel-art masters, era-specific sprites and animations still need production integration and phone-size acceptance. Component names are not evidence of production art.
8. **P1 Monetization:** Shop purchases and rewarded ads are intentionally disabled without provider-backed payment/ad completion. LocalStorage saves are editable by players: production currency fraud requires a trusted backend or server-side entitlement validation.
9. **P2 Citadel/Hell:** Citadel visuals preserved; the Broker's high-stakes mechanics are disabled until bounded opt-in losses and recovery are decided and tested.
10. **P2 Historical content:** Richard's portrait map, detailed Legends anthology, historical encounter differentiation and event skinned worlds are not yet verified as built.
